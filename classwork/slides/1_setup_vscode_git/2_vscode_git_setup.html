Setting Up VSCode

Install the Quarto Extension

  • Click the Extensions icon (four squares, left sidebar) — or Ctrl+Shift+X / Cmd+Shift+X
  • Search for “Quarto”
  • Click Install

Install the Python Extension

  • Same Extensions view
  • Search for “Python” (the one published by Microsoft)
  • Click Install

The VSCode Layout

  • Explorer (left): your files and folders
  • Editor (center): where you write/edit
  • Terminal (bottom): where you’ll run commands — same commands you’d use in Terminal (Mac) or Git Bash (Windows)
  • Source Control (left sidebar, branch-looking icon): where Git lives

Double-Checking Git

Step 1: Open the Integrated Terminal

  • In VSCode: View → Terminal
  • From now on, this is where all our git and command-line work happens — no need for a separate app

Step 2: Confirm Your Name & Email

git config user.name
git config user.email
  • You should see something like:
Jane Doe
janedoe@email.com
  • If it’s blank, set it now:
git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"

Step 3: Confirm Your SSH Connection

  • You should have already created an SSH key and added it to GitHub at home. Let’s confirm it actually works:
ssh -T git@github.com
  • First time: type yes to trust GitHub
  • Success looks like: “Hi your-username! You’ve successfully authenticated…”
  • If that worked, you’re done here — skip ahead to “Accessing the Course Repo”

If That Didn’t Work

  • Check for a key:
ls ~/.ssh
  • Look for id_ed25519 and id_ed25519.pub. If you see them, skip to “Add the Key to GitHub” below — the problem is on GitHub’s end, not yours.
  • If they’re missing, generate one:
ssh-keygen -t ed25519 -C "your_github_email@example.com"
  • Press Enter through the prompts (accept the default location, no passphrase is fine)
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

Copy Your Public Key

  • Mac:
pbcopy < ~/.ssh/id_ed25519.pub
  • Windows:
clip < ~/.ssh/id_ed25519.pub
  • This might not work, if so:
cat \~/.ssh/id_ed25519.pub \| clip

Add the Key to GitHub

  • Go to github.com → Settings → SSH and GPG keys → New SSH key
  • Title: “My Laptop” (or something you’ll recognize)
  • Key type: Authentication
  • Paste the key, click Save

Test the Connection Again

ssh -T git@github.com
  • Success looks like: “Hi your-username! You’ve successfully authenticated…”
  • If you get an error, raise your hand — we’ll fix it together.

Accessing the Course Repo

Where Course Files Live

  • All of our slides, data, and activities live in a shared course repository on GitHub
  • You’ll clone it (make a local copy) so you always have the current files

Before You Clone: Make a Home for Your Class Files

  • Somewhere sensible on your computer (e.g. inside Documents), create one new folder called computation_4_linguists
  • This will hold both the course repo and your own repo, side by side — not buried in Downloads or scattered across your Desktop
  • Everything below goes inside this folder

Cloning the Course Repo

  • In VSCode: open the Command Palette (Ctrl+Shift+P / Cmd+Shift+P)
  • Type “Git: Clone”, press Enter
  • Paste the repo URL:

  • When prompted for a location, choose your computation_4_linguists folder — VSCode will create a 301_2026 folder inside it, then click Open when prompted

Alternative: Do It in the Terminal

git clone https://github.com/Winjapati/301_2026

Opening and Rendering a .qmd File

  • In the Explorer (left sidebar), open 301_2026/ and click any .qmd file to open it
  • Click Preview at the top of the editor to preview it as a webpage/slideshow

Setting Up Your Own Repo

Create a Repository on GitHub

  • Go to github.com → New repository
  • Name it LIN_301 (or something similar)
  • Choose Public
  • Check the box to add a README.md file

Clone It Into VSCode

  • Command Palette → “Git: Clone” → paste your repo’s URL
  • When prompted for a location, choose the same computation_4_linguists folder you cloned the course repo into — not a new/different one
  • Open it when prompted

One Folder, Both Repos

computation_4_linguists/
├── 301_2026/      (shared course repo — pull for updates)
└── LIN_301/       (your repo — where you push your work)
  • Open computation_4_linguists in VSCode (File → Open Folder) and you’ll see both repos in the Explorer at once
  • This is the folder you’ll open every class from now on

Testing the Whole Pipeline

Edit, Commit, Push

  1. Open README.md in the editor, add a sentence, save (Ctrl+S / Cmd+S)
  2. Click the Source Control icon (branch icon, left sidebar)
  3. Hover over the changed file, click + to stage it
  4. Type a commit message (e.g. “first commit”)
  5. Click the checkmark (✓) to commit

This Is Crucial!

Committing only saves the change locally. You must also click Sync Changes (or … → Push) to actually send it to GitHub!

Verify It Worked

  • Go to your repo on github.com
  • Refresh the page
  • You should see your edited README.md with your new sentence

Activity

Activity 1: Add and Push a New File

  1. In your LIN_301 repo, create a new file called day2_notes.md
  2. Describe what you’ve done so far in today’s class in this file.
  3. Save, then check Source Control — notice this file is marked differently than README.md was earlier (untracked, not modified)
  4. Stage → commit → push, same as before

Activity 2: Make (and Fix) Your First Merge Conflict

Goal: see a conflict happen on purpose, in a safe spot, before it happens to you by accident.

  1. On github.com, open your LIN_301 repo → click into README.md → click the pencil icon to edit
  2. Edit the same line you edited earlier today, then commit the change directly on GitHub
  3. Back in VSCode — without pulling first — edit that same line locally, but differently. Save, stage, commit.
  4. Try to push. What happens?
  5. Pull. VSCode will report a conflict — open the file and look for the conflict markers: <<<<<<<, =======, >>>>>>>
  6. Decide what the line should actually say, edit the file to remove the markers and leave only the final version, then stage, commit, and push
  7. Refresh github.com to confirm your resolved version made it up

If You Get Stuck

Conflicts are the one Git moment that can feel scary the first time. Raise your hand — this is exactly the kind of thing we want to practice together, with a safety net, before it happens on a real assignment.

Troubleshooting

If VSCode Asks for a Username/Password

git remote -v   # you'll likely see https://github.com/...
git remote set-url origin git@github.com:<YourUser>/<YourRepo>.git
git remote -v   # now it should show git@github.com:...
  • Try pushing again

In Case of Emergency: Personal Access Token (PAT)

  • GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
  • Generate new token → name it laptop-vscode → check the repo scope → Generate
  • Copy it immediately — you won’t see it again
  • Use it as your password the next time VSCode prompts you
